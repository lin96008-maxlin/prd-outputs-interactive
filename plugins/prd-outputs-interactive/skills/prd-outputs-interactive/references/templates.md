# PRD 模板

## 使用规则

- 默认只维护一份主 PRD。
- 最终章节名使用普通业务语言，不输出内部方法名。
- 详细需求是正文主体；页面、字段、状态、权限、异常和验收优先写在对应需求中。
- 多个需求共用的规则集中写一次，通过需求编号引用。
- 没有内容的章节、字段和表格不输出。
- 正文只描述当前有效需求；历史变化只有在影响兼容、迁移、验收或责任判断时才记录。

## 4. 共用规则与数据

只记录多个需求共同使用的内容，例如：

- 统一状态、时间、金额或编号规则；
- 权限合并和数据范围；
- 数据来源、统计口径、刷新和去重；
- 通知、日志、审计和数据保留；
- 外部系统边界和失败处理；
- 跨页面或跨流程的一致行为。

规则只影响一个需求时，写回对应详细需求，不在本章重复。

## 辅助文档

长期接力、材料复杂或质量检查需要留痕时，才创建交接文档、文档索引、质量记录或项目约束。辅助文档不承载第二套需求规格。

## 输出前检查

- 章节名是否直白，产品、研发和测试是否能直接理解；
- 输入中出现的每个操作是否在详细需求、验收或待确认项中有落点；
- 字段必填、默认值、可编辑角色、批量失败方式和指标公式是否有明确依据；
- 详细需求是否写清规则、结果、权限、状态、异常和恢复；
- 页面、字段、状态和通知是否优先跟随对应业务需求，而不是重复拆章；
- 共用规则是否只写一次；
- 待确认内容是否说明影响、责任人、下一步和是否阻断；
- 是否删除空章节、空表格、模板提示和维护过程说明。
